# مرجع جامع و تخصصی معماری و راه‌اندازی Rathole Multi-Location Tunnel
## (راهنمای جامع ادغام با پنل سنایی 3x-ui: ترافیک وب WS و XHTTP + حالت گیمینگ 0-RTT Vision + ضد پکت‌لاس KCP)

این سند مرجع فنی، معماری و عملیاتی پروژه **Rathole Manager** با تمرکز بر ادغام یکپارچه با **پنل گرافیکی سنایی ([3x-ui](https://github.com/MHSanaei/3x-ui))** روی سرور خارج است. در این شیوه، شما نیازی به ویرایش دستی فایل‌های پیچیده JSON یا راه‌اندازی دستی Xray ندارید؛ بلکه تمامی کاربران، حجم‌ها، تاریخ انقضا و اینباندها را در پنل تحت وب سنایی مدیریت می‌کنید و تانل معکوس Rathole ترافیک پورت ۴۴۳ سرور ایران را مستقیماً به اینباندهای ۳x-ui تحویل می‌دهد.

## ۱. معماری سیستم و نحوه کارکرد تانل معکوس

```
+-----------------------------------------------------------------------------------+
| [کاربران و گیمرها]                                                                |
+-----------------------------------------------------------------------------------+
           | (ارتباط HTTPS امن به پورت 443 سرور ایران)
           v
+-----------------------------------------------------------------------------------+
| [سرور ایران] (شنونده / Listener روی پورت 443)                                     |
|  - Nginx لایه ۷: تفکیک مسیرها (/node1 -> WS, /xhttp1 -> XHTTP) + دفاع پروب فعال  |
|  - Nginx لایه ۴: عبور مستقیم SNI گیمینگ (game.example.com -> بدون بازگشایی TLS)    |
|  - Rathole Server: مالتی‌پلکس داده‌ها داخل یک کانال رمزنگاری‌شده معکوس            |
+-----------------------------------------------------------------------------------+
           ^
           | (تانل معکوس امن: اتصال از خارج به ایران برقرار می‌شود!)
+-----------------------------------------------------------------------------------+
| [سرور خارج] (نود / Initiator + پنل محبوب سنایی 3x-ui)                             |
|  - Rathole Node: دریافت استریم از ایران و تحویل به پورت‌های لوکال 127.0.0.1        |
|  - پنل سنایی (3x-ui): مدیریت اینباندها، کاربران، حجم، تاریخ و هسته Xray            |
|     * اینباند 10001 (VLESS-WS روی 127.0.0.1)                                      |
|     * اینباند 10003 (VLESS-XHTTP روی 127.0.0.1)                                   |
|     * اینباند 10002 (VLESS-Vision-TLS لایه ۴ روی 127.0.0.1 مخصوص بازی)            |
+-----------------------------------------------------------------------------------+
```

### ویژگی‌های کلیدی این معماری:
1. **تک‌پورت بودن سرور ایران (Single-Port 443)**: تمامی ترافیک وب، استریم XHTTP، گیمینگ لایه ۴، و پنل‌های وب از همان پورت استاندارد ۴۴۳ رد می‌شوند.
2. **پنهان ماندن پورت‌های خارج (127.0.0.1)**: اینباندهای 3x-ui را روی `127.0.0.1` گوش می‌دهیم تا پورت‌ها مستقیماً روی آی‌پی خارج باز نمانند و اسکن نشوند. ترافیک فقط از داخل تانل ایران وارد آن‌ها می‌شود.
3. **دفاع فعال در برابر اسکنرهای فیلترینگ**: اگر فیلترچی آدرس سرور ایران شما را با مرورگر یا بات باز کند، یک وب‌سایت مدرن و واقعی فارسی شرکتی دریافت می‌کند و پورت بلاک نمی‌شود.

## ۲. پیش‌نیازها و تنظیم رکوردهای DNS

| مورد | مقدار پیشنهادی | توضیحات |
| :--- | :--- | :--- |
| **سرور ایران** | اوبونتو 20.04/22.04/24.04 یا دبیان 11/12 | حداقل ۱ گیگابایت رم، دسترسی روت |
| **سرور خارج** | اوبونتو یا دبیان | لوکیشن با پینگ پایین (آلمان، هلند، ترکیه و...) |
| **دامنه اصلی** | مثلاً `iran.example.com` | رکورد A در Cloudflare مستقیم به **IP سرور ایران** (پروکسی ☁️ خاموش / DNS Only) |
| **ساب‌دامین گیم** | مثلاً `game.example.com` | رکورد A در Cloudflare مستقیم به **IP سرور ایران** (پروکسی ☁️ خاموش / DNS Only) |
| **پورت‌های باز** | `80/tcp`, `443/tcp`, `443/udp` | روی فایروال سرور ایران باز باشند |

## ۳. نصب پنل سنایی (3x-ui) روی سرور خارج

روی **سرور خارج**، دستور رسمی نصب پنل سنایی را اجرا کنید:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```
- در مراحل نصب، نام کاربری، رمز عبور و پورت پنل (مثلاً `2053`) را انتخاب کنید.
- پس از اتمام نصب، وارد پنل وب سنایی شوید:  
  👉 `http://<IP_KHAREJ>:2053/`

> [!TIP]
> بعد از نصب ۳x-ui وارد منوی **تنظیمات پنل (Panel Settings)** -> **تنظیمات Xray (Xray Settings)** شوید و اطمینان حاصل کنید آخرین نسخه هسته Xray (نسخه 1.8.23 به بالا) انتخاب شده باشد تا از پروتکل **XHTTP** نیز پشتیبانی کند.

## ۴. گام ۱: راه‌اندازی سرور ایران (پنل و سرور مرکزی)

وارد SSH **سرور ایران** شوید و مخزن را کلون و نصب کنید:

```bash
# نصب ابزارهای پایه
apt-get update -y && apt-get install -y git curl

# دریافت مخزن
git clone https://github.com/oldrcesupport/rathole-tunnel.git /root/rathole-manager

# اجرای نصاب پنل ایران
cd /root/rathole-manager
sudo bash install-panel.sh
```

### ثبت دامنه اصلی و دریافت SSL رایگان Let's Encrypt:
```bash
sudo ratholectl cert iran.example.com admin@example.com
```

### بهینه‌سازی سرعت هسته سیستم (BBR و بافرهای شبکه):
```bash
sudo ratholectl tune
```

### فعال‌سازی پنل مدیریت هاب تحت وب (RatholeHub):
```bash
sudo ratholectl hub on 2087
```
🌐 آدرس پنل مانیتورینگ ایران: `https://iran.example.com/hub/`

## ۵. گام ۲: راه‌اندازی نود تانل در سرور خارج

### الف) ایجاد نودها روی سرور ایران:
روی سرور ایران، پورت‌های اینباندهای ۳x-ui را تعریف کنید:
```bash
# نود ترافیک عادی وب‌سوکت (پورت 10001 در 3x-ui):
sudo ratholectl add node1 10001

# نود ترافیک استتار نوین XHTTP (پورت 10003 در 3x-ui):
sudo ratholectl add xhttp1 10003
```
برای مشاهده توکن اتصال نود:
```bash
sudo ratholectl token node1
sudo ratholectl token xhttp1
```

### ب) اجرای نصاب نود روی سرور خارج:
وارد سرور خارج شوید و تانل را نصب کنید:
```bash
apt-get update -y && apt-get install -y git curl
git clone https://github.com/oldrcesupport/rathole-tunnel.git /root/rathole-manager
cd /root/rathole-manager
sudo bash install-node.sh
```

سپس نود را به سرور ایران متصل کرده و سرویس‌ها را اضافه کنید:
```bash
# مشخص کردن آدرس سرور ایران
sudo ratholenode set SERVER iran.example.com:443

# اتصال سرویس وب‌سوکت
sudo ratholenode add-svc node1 <TOKEN_NODE1> 10001

# اتصال سرویس XHTTP
sudo ratholenode add-svc xhttp1 <TOKEN_XHTTP1> 10003
```

بررسی سلامت اتصال تانل در خارج:
```bash
sudo ratholenode status
```
اگر خروجی سبز بود و وضعیت سرویس‌ها `active / connected` را نشان داد، تانل کاملاً آماده است!

## ۶. گام ۳: ساخت اینباند ترافیک عادی الف - پروتکل WebSocket (WS) در 3x-ui

وارد پنل وب **3x-ui** روی سرور خارج شوید (`http://<IP_KHAREJ>:2053`).  
به منوی **ورودی‌ها (Inbounds)** بروید و روی **افزودن ورودی (Add Inbound)** کلیک کنید:

| فیلد در پنل سنایی | مقدار تنظیمی | توضیحات |
| :--- | :--- | :--- |
| **توضیحات (Remark)** | `Iran-WS` | نام دلخواه برای اینباند |
| **پروتکل (Protocol)** | `vless` | بهترین پروتکل سبک و پرسرعت |
| **آی‌پی گوش دادن (Listening IP)** | `127.0.0.1` | **بسیار مهم**: پورت فقط لوکال باز می‌شود تا مستقیم بلاک نشود |
| **پورت (Port)** | `10001` | دقیقاً مطابق پورتی که در `ratholectl add node1 10001` دادید |
| **انتقال (Transmission)** | `ws` (WebSocket) | پروتکل وب‌سوکت |
| **مسیر (Path)** | `/node1` | **بسیار مهم**: دقیقاً مطابق نام سرویسی که ساختید |
| **امنیت (Security)** | `none` (هیچ) | **نکته کلیدی**: Nginx ایران SSL را رمزگشایی می‌کند |

### ⚙️ تنظیم خروجی لینک در 3x-ui برای اتصال کلاینت:
در همان پنجره ساخت اینباند (یا با زدن دکمه ویرایش کلاینت):
- در بخش **تنظیمات پیشرفته / تنظیمات استریم (Client / Stream Settings)**:
  - فیلد **Address (آدرس)**: دامنه سرور ایران شما (`iran.example.com`)
  - فیلد **Port (پورت)**: `443`
  - فیلد **TLS**: فعال (`tls`) با SNI: `iran.example.com`

حالا هر کاربری در این اینباند بسازید، کد QR و لینک تولیدی آن مستقیماً با پروتکل TLS به سرور ایران روی پورت ۴۴۳ وصل می‌شود و تانل آن را به خارج می‌فرستد!

## ۷. گام ۴: ساخت اینباند ترافیک عادی ب - پروتکل فوق‌پیشرفته XHTTP (SplitHTTP) در 3x-ui

پروتکل **XHTTP** ارتباط را به جای وب‌سوکت طولانی، در قالب ریکوئست‌های استاندارد HTTP/2 POST ارسال می‌کند و برای سیستم‌های فیلترینگ هوشمند، ترافیک کاربر شبیه کار با یک سامانه اداری یا آپلود فایل به نظر می‌رسد.

در پنل **3x-ui** روی دکمه **افزودن ورودی (Add Inbound)** کلیک کنید:

| فیلد در پنل سنایی | مقدار تنظیمی | توضیحات |
| :--- | :--- | :--- |
| **توضیحات (Remark)** | `Iran-XHTTP-Stealth` | نام دلخواه |
| **پروتکل (Protocol)** | `vless` | پروتکل پایه |
| **آی‌پی گوش دادن (Listening IP)** | `127.0.0.1` | فقط ارتباط لوکال تانل |
| **پورت (Port)** | `10003` | مطابق پورتی که در `ratholectl add xhttp1 10003` دادید |
| **انتقال (Transmission)** | `xhttp` (یا splithttp) | پروتکل نسل جدید انتقالات Xray |
| **مسیر (Path)** | `/xhttp1` | مطابق نام سرویس xhttp1 در ایران |
| **حالت (Mode)** | `auto` (یا packet-up) | تطبیق هوشمند استریم |
| **امنیت (Security)** | `none` | گواهی SSL در سرور ایران هندل می‌شود |

### ⚙️ تنظیم خروجی لینک در 3x-ui:
- **Address**: `iran.example.com`
- **Port**: `443`
- **TLS**: فعال (`tls`) با SNI: `iran.example.com`

> [!NOTE]
> هسته پروژه Rathole Manager با تنظیمات اختصاصی Nginx (`chunked_transfer_encoding on` و `proxy_request_buffering off`) استریم XHTTP را با کمترین تاخیر و بدون بافرینگ عبور می‌دهد.

## ۸. گام ۵: ساخت اینباند گیمینگ فوق‌سریع (L4 SNI + VLESS-Vision + UDP FullCone) در 3x-ui

حالت گیمینگ مخصوص بازی‌های آنلاین (CoD, CS2, Dota 2, FIFA) و ویس است:
- صفر میلی‌ثانیه تاخیر اضافه (**0-RTT**).
- حذف لایه‌های وب؛ ترافیک به صورت خام از لایه ۴ رد می‌شود.
- بسته‌های UDP بازی به صورت مستقیم و بدون بافرینگ (FullCone) مخابره می‌شوند.

### مرحله ۱: تعریف سرویس گیم روی سرور ایران
روی سرور ایران، ساب‌دامین اختصاصی گیم را تعریف و گواهی آن را صادر کنید:
```bash
sudo ratholectl game add game1 10002 game.example.com
sudo ratholectl game cert game.example.com
```
دستور زیر را بزنید تا توکن گیم را ببینید:
```bash
sudo ratholectl game ls
```

### مرحله ۲: انتقال گواهی SSL به سرور خارج
چون در حالت گیمینگ لایه ۴، سرور ایران در TLS دخالت نمی‌کند، هندشیک TLS روی سرور خارج انجام می‌شود. فایل‌های گواهی را به سرور خارج بفرستید:
```bash
ssh root@<IP_KHAREJ> "mkdir -p /etc/xray-certs/game.example.com"
scp /etc/letsencrypt/live/game.example.com/fullchain.pem root@<IP_KHAREJ>:/etc/xray-certs/game.example.com/
scp /etc/letsencrypt/live/game.example.com/privkey.pem root@<IP_KHAREJ>:/etc/xray-certs/game.example.com/
```

### مرحله ۳: اتصال سرویس گیم در نود خارج
روی **سرور خارج** دستورات زیر را اجرا کنید:
```bash
sudo ratholenode add-svc game1 <GAME_TOKEN> 10002
sudo ratholenode fakeweb start 8081
```

### مرحله ۴: ساخت اینباند گیمینگ در پنل سنایی (3x-ui)
در پنل **3x-ui** یک اینباند جدید بسازید:

| فیلد در پنل سنایی | مقدار تنظیمی | توضیحات |
| :--- | :--- | :--- |
| **توضیحات (Remark)** | `Game-Vision-Direct` | نام سرویس گیمینگ |
| **پروتکل (Protocol)** | `vless` | پروتکل اختصاصی گیمینگ |
| **آی‌پی گوش دادن (Listening IP)** | `127.0.0.1` | امنیت لوکال |
| **پورت (Port)** | `10002` | پورت لوکال تانل گیمینگ |
| **انتقال (Transmission)** | `tcp` | بدون لایه وب؛ انتقال مستقیم TCP |
| **امنیت (Security)** | **`tls`** | **مهم**: در حالت گیمینگ، TLS داخل سنایی روشن است |
| **جریان (Flow)** | **`xtls-rprx-vision`** | شتاب‌دهنده مستقیم سخت‌افزاری هسته Xray |
| **گواهی (Certificate)** | مسیر فایل‌ها | مسیر گواهی انتقالی: `/etc/xray-certs/game.example.com/fullchain.pem` و فایل کلید: `/etc/xray-certs/game.example.com/privkey.pem` (یا بارگذاری مستقیم در تب Certificate پنل سنایی) |
| **بازگشت (Fallbacks)** | پورت `8081` | پورت فال‌بک وب لوکال |

### ⚙️ تنظیم خروجی لینک گیمینگ در 3x-ui:
- **Address**: `game.example.com` (یا IP سرور ایران)
- **Port**: `443`
- **SNI**: `game.example.com`
- **Flow**: `xtls-rprx-vision`

## ۹. گام ۶: فعال‌سازی سلاح ضد پکت‌لاس گیم (KCP / UDP+FEC روی پورت 443)

در ساعات اوج مصرف اینترنت یا شب‌ها که اینترنت بین‌الملل دچار نوسان و پکت‌لاس می‌شود:

1. **روی سرور ایران**:
   ```bash
   sudo ufw allow 443/udp
   sudo ratholectl kcp on 443 balanced
   sudo ratholectl kcp status
   ```
   *(کلید تصادفی امن نمایش داده شده را کپی کنید).*

2. **روی سرور خارج**:
   ```bash
   sudo ratholenode kcp on <IP_IRAN>:443 <کلید_دریافتی> balanced
   ```

### چرا این کار مشکل پکت‌لاس گیم را حل می‌کند؟
- بستر تانل بین دو سرور بلافاصله به پروتکل UDP با استتار الگوی QUIC گوگل و قابلیت **تصحیح خطای ریاضی Reed-Solomon (FEC)** تغییر می‌کند.
- **نیازی به تغییر هیچ کانفیگی در پنل ۳x-ui یا گوشی کاربران نیست!** تمامی اینباندهای سنایی (چه WS، چه XHTTP، چه Vision گیمینگ) ترافیکشان به صورت خودکار از این بستر ضد پکت‌لاس عبور خواهد کرد.

---

## ۱۰. سیستم دفاع فعال Nginx در برابر اسکنرهای فیلترچی (Active Probe Defense)

سیستم فیلترینگ با ارسال درخواست‌های کاوشگر جعلی (Active Probes) تلاش می‌کند پروکسی‌ها را کشف و IP آن‌ها را فیلتر کند. پروژه Rathole Manager مجهز به سپرهای دفاعی زیر است:

1. **جذب پروب فعال با بازگشت 200 OK**: اگر یک اسکنر یا فایروال آدرس سرور شما را بدون هدرهای وب‌سوکت یا XHTTP اسکن کند، Nginx بلافاصله وب‌سایت شرکتی واقعی فارسی که در ریشه قرار دارد را با کد `200 OK` بازمی‌گرداند.
2. **پنهان‌سازی خطاهای بالادستی**: حتی اگر نود خارج یا پنل ۳x-ui موقتاً قطع شود، گزینه‌های `proxy_intercept_errors on` و `error_page 502 503 504 =200 /;` مانع از لو رفتن خطای 502/503 سرور پروکسی می‌شوند.
3. **پنهان‌سازی هویت سرور**: دستور `server_tokens off;` و هدرهای سازگار مدرن مرورگرها فعال هستند.

## ۱۱. تنظیمات بهینه کلاینت‌ها (v2rayNG, Sing-box, Nekobox)

1. **برای گیمینگ**: در نرم‌افزار گوشی یا ویندوز، حتماً گزینه **TUN Mode** را فعال کنید تا بسته‌های UDP بازی مستقیماً از تانل رد شوند.
2. **غیرفعال‌سازی Multiplex (Mux)**: برای کانفیگ‌های گیمینگ، قابلیت Mux را در نرم‌افزار خاموش کنید تا بسته‌ها در صف تجمیع نمانند و پینگ آنی بماند.
3. **استفاده از نسخه جدید کلاینت‌ها**: برای اتصال با پروتکل نوین XHTTP، از نسخه‌های به‌روز نرم‌افزارها (مانند v2rayNG 1.8.20+ یا Sing-box 1.9+ یا v2rayN 6.40+) استفاده کنید.

## ۱۲. جعبه‌ابزار دستورات مدیریتی و خطایابی

```bash
# بررسی سلامت کامل سیستم و کانفیگ Nginx:
sudo ratholectl doctor

# مشاهده وضعیت نودها، پورت‌ها و لایسنس:
sudo ratholectl status

# تولید مجدد تنظیمات و بارگذاری مجدد بدون قطعی کاربران (Zero-Downtime):
sudo ratholectl regen

# مشاهده لاگ‌های سیستم با سانسور خودکار توکن‌های امنیتی:
sudo ratholectl logs 50

# لیست سرویس‌های گیمینگ فعال:
sudo ratholectl game ls

# وضعیت سرویس ضد پکت‌لاس KCP:
sudo ratholectl kcp status
```
